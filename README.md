# Бот "Нові проєкти документів Дніпровської міськради"

Перевіряє сторінку пошуку проєктів документів Дніпровської міської ради
і публікує в Telegram кожен новий проєкт (назву, вид і дату публікації).
Працює через GitHub Actions за розкладом — без власного сервера, повністю
безкоштовно (в межах безкоштовного тарифу GitHub Actions).

## Як це працює

Замість того щоб парсити всю HTML-сторінку (вона віддає 403 автоматичним
запитам без правильних заголовків), скрипт напряму звертається до
внутрішнього ендпоінта, який використовує сама форма пошуку на сайті:

```
POST https://dniprorada.gov.ua/uk/Widgets/GetCouncilProjectDocuments
Body: DateRange=17.08.2026 - 18.08.2026&DocHeader=&DocTypeCode=0
```

У відповідь повертається таблиця з проєктами за вказаний період.
Скрипт запам'ятовує, які проєкти вже було надіслано (файл
`seen_projects.json`, який після кожного запуску автоматично коміт(иться)
назад у репозиторій), і надсилає в Telegram лише нові.

## Крок 1. Бот уже створений ✅

Токен вже вписаний у `scraper.py` (константа `TELEGRAM_TOKEN`), нічого
робити не потрібно. Бот: `@dniproradamediabot`.

## Крок 2. Створити канал і додати бота

1. Створіть Telegram-канал (публічний або приватний).
2. Додайте свого бота як адміністратора каналу (потрібні права на
   публікацію повідомлень).
3. Дізнайтеся `chat_id` каналу:
   - Якщо канал публічний — можна просто використати `@username_каналу`
     замість `chat_id` у скрипті.
   - Якщо приватний — надішліть у канал будь-яке повідомлення, потім
     відкрийте у браузері:
     `https://api.telegram.org/bot8562718356:AAFCqZv9o3A8p_QlCRTrQiPZ1Bo3WQRPN9U/getUpdates`
     і знайдіть `"chat":{"id": -100XXXXXXXXXX, ...}` — це і є `chat_id`.
4. Відкрийте `scraper.py`, знайдіть рядок:
   ```python
   TELEGRAM_CHAT_ID = os.environ.get("TELEGRAM_CHAT_ID", "ВСТАВТЕ_СЮДИ_CHAT_ID")
   ```
   і замініть `"ВСТАВТЕ_СЮДИ_CHAT_ID"` на реальний `chat_id` (або
   `"@username_каналу"`, якщо канал публічний).

## Крок 3. Розмістити код на GitHub

1. Створіть новий репозиторій на GitHub (публічний або приватний —
   на ваш розсуд).
2. Завантажте туди всі файли з цього комплекту, зберігаючи структуру:
   - `scraper.py` (з уже вписаним chat_id з кроку 2)
   - `requirements.txt`
   - `seen_projects.json`
   - `.github/workflows/check_projects.yml`

Секрети в GitHub налаштовувати не потрібно — токен і chat_id вже прямо
в коді. Якщо колись захочете прибрати їх з коду (наприклад, якщо репозиторій
стане публічним і ви передумаєте щодо безпеки) — інструкція в коментарях
всередині `check_projects.yml` та `scraper.py`.

## Крок 4. Перший тестовий запуск

1. Перейдіть у вкладку **Actions** репозиторію.
2. Оберіть workflow **"Check Dnipro council draft projects"**.
3. Натисніть **Run workflow** (це запускає його вручну, не чекаючи
   розкладу).
4. Перевірте лог: скрипт повинен вивести кількість знайдених проєктів.
   При **першому** запуску повідомлення в Telegram не надсилаються —
   бот просто запам'ятовує всі поточні проєкти як "вже відомі" (інакше
   канал одразу засипало б сотнями старих проєктів). Усі наступні запуски
   надсилатимуть лише нові.

Після цього workflow буде запускатися автоматично кожні 3 години
(налаштовано в `check_projects.yml`, рядок `cron: "0 */3 * * *"`).

## Якщо щось не працює

- **GitHub Actions вимикає розклад сам:** якщо в репозиторії 60 днів
  не було жодної активності, GitHub автоматично вимикає scheduled
  workflows. Раз на 1–2 місяці зайдіть в Actions і за потреби натисніть
  "Enable workflow" — або зробіть будь-який комміт.
- **Скрипт повертає помилку 403 / порожню відповідь:** сайт може
  блокувати запити з дата-центрових IP-адрес GitHub Actions (це відомий
  захист деяких державних сайтів). У такому разі є два шляхи:
  1. Запускати той самий `scraper.py` не на GitHub Actions, а на
     будь-якому VPS/домашньому сервері зі звичайною IP-адресою
     (через `cron`, раз на 3 години).
  2. Переписати запит через headless-браузер (Playwright), який більше
     схожий на звичайного відвідувача — це важче й трохи повільніше,
     але теж можна запускати безкоштовно на GitHub Actions. Якщо
     знадобиться — напишіть, підготую такий варіант.
- **Змінити частоту перевірки:** поміняйте рядок `cron` у
  `.github/workflows/check_projects.yml`. Наприклад, раз на годину —
  `"0 * * * *"`, раз на добу — `"0 6 * * *"`.
- **Фільтр за видом документа:** якщо потрібні лише, наприклад, проєкти
  рішень міськради (без розпоряджень голови), задайте в workflow змінну
  середовища `DOC_TYPE_CODE: "3"` (0 = всі, 2 = виконком, 3 = міськрада,
  4 = розпорядження голови).
